# CampusHub

Платформа самообслуживания университетского кампуса

CampusHub объединяет доступ к аккаунтам, операции банкомата и работу торговых
автоматов. Текущая версия реализует бизнес-правила этих сервисов и проверяет их
с помощью исполняемых спецификаций на Gherkin.

## Возможности

- **Банкомат:** снятие доступных средств, отказ при недостаточном балансе или
  некорректной сумме без изменения баланса. Суммы задаются целыми числами;
  реальные деньги не используются.
- **Доступ к аккаунту:** блокировка после трёх неудачных попыток входа подряд.
  Успешный вход сбрасывает счётчик ошибок; заблокированный аккаунт отклоняет
  вход даже с правильным паролем.
- **Кофемашина:** приготовление капучино при достаточном запасе молока,
  списание количества по рецепту и сохранение запаса при отклонённом заказе.

Состояние хранится в Python-объектах и не сохраняется между запусками. Компоненты
пока не связаны общей системой счетов, HTTP API или веб-интерфейсом. Модуль входа
моделирует правила блокировки: пароль хранится в памяти, это не готовая система
аутентификации для реального приложения.

## Подготовка окружения

Нужны Python 3.11 или новее и виртуальное окружение в `venv/`.
Команды выполняются из корня репозитория.

Активировать окружение:

```bash
source venv/bin/activate
```

Установить пакет и инструменты разработки:

```bash
python -m pip install -e ".[dev]"
```

Если окружение создано без pip, для установки можно использовать
[uv](https://docs.astral.sh/uv/):

```bash
uv pip install --python venv/bin/python -e ".[dev]"
```

Затем подключить Git-хук:

```bash
pre-commit install
```

Установка с флагом `-e` позволяет тестам сразу использовать изменения в `src/`.
У бизнес-компонентов нет сторонних зависимостей. Версии инструментов разработки
зафиксированы в `pyproject.toml`.

## Проверки поведения

Запустить все спецификации:

```bash
behave
```

Запустить сценарии одного компонента:

```bash
behave features/authentication.feature
```

Сценарии проверяют отклонённые и успешные операции, а также граничные значения
баланса, числа попыток входа и запаса молока. Каждый сценарий создаёт новые
объекты: база данных, сервер и общее состояние тестов не нужны.

Git-хук запускает все сценарии перед каждым коммитом, даже если изменилась только
документация. Падающий сценарий останавливает коммит. Та же проверка вручную:

```bash
pre-commit run --all-files
```

При коммите окружение `venv` должно быть активировано: хук использует
`python -m behave` из текущего окружения, в котором установлен CampusHub.
После клонирования репозитория хук нужно установить заново: Git не переносит
установленные хуки.

## Структура кода

```text
src/campushub/
  atm.py        Правила снятия средств и баланс
  auth.py       Попытки входа и блокировка аккаунта
  vending.py    Приготовление капучино и запас молока
features/
  *.feature     Спецификации поведения
  steps/        Python-шаги и проверки результатов
```

Бизнес-компоненты не зависят от behave. Шаги связывают сценарий с подготовкой
данных, вызовом публичной операции и проверкой результата и состояния.
Отказы банкомата и кофемашины выражены предметными исключениями; попытка входа
возвращает признак успеха. Неожиданные исключения приводят к падению сценария.

Дальнейшее развитие: связать компоненты через общие операции со счетами,
затем предоставить доступ к ним через API. В текущей версии это ещё не реализовано.
